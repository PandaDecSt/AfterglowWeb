# 2026-08-02 GPU Skinning 双重蒙皮根因分析

## 问题现象

启用 GPU Compute Skinning 后，模型"大部分顶点飞出/错位"，完全不可用。CPU 端蒙皮（VS 内蒙皮）正常。

## 根因

**`Float32Array` 写入 u32 标志位导致位模式不匹配。**

`sceneData` 是 `Float32Array(80)`，代码用 `sceneData[44] = 1` 写入 GPU Skinning 开关标志。这写入的是 **IEEE 754 float 1.0**，位模式为 `0x3F800000`。

WGSL shader 中 `flags` 声明为 `u32`，按 u32 读取同一内存位置，得到 `0x3F800000 = 1065353216`。

```wgsl
// VS 中的判断
if ((scene.flags & 1u) != 0u) {  // 1065353216 & 1 = 0 → 永远走 else 分支！
    skinPos = vec4<f32>(in.position, 1.0);  // 跳过 VS 蒙皮（期望走这里）
} else {
    // VS 端蒙皮（实际走了这里 → 双重蒙皮！）
}
```

`1065353216 & 1 = 0`，所以 **flags 从未生效**，VS 一直在已蒙皮的数据上再做一次 VS 端蒙皮 → 双重蒙皮 → 顶点飞出。

## 修复

用 `Uint32Array` 视图写入整数值，确保 shader 读到 `1` 而非 `0x3F800000`：

```typescript
// 之前（错误）
private sceneData = new Float32Array(80);
this.sceneData[44] = this.gpuSkinningEnabled ? 1 : 0;  // 写入 float 1.0

// 之后（正确）
private sceneData = new Float32Array(80);
private sceneDataU32 = new Uint32Array(this.sceneData.buffer);
this.sceneDataU32[44] = this.gpuSkinningEnabled ? 1 : 0;  // 写入 uint32 1
```

shadow 场景的 `shadowSceneData[32]` 同理修复。

## 排查过程

### 第一阶段：怀疑 compute shader 动态索引

最初假设是 `array<mat4x4<f32>>` 的动态索引在用户 GPU 上不工作。依次尝试：

1. `array<mat4x4<f32>>` → `array<vec4<f32>>` + 手动列向量乘法 → 仍扭曲
2. `array<vec4<f32>>` → `array<u32>` + `bitcast<f32>` + 全标量展开 → 仍扭曲
3. 拆分骨骼索引/权重到独立 buffer（`array<vec4<u32>>` → `array<u32>`）→ 仍扭曲

### 第二阶段：怀疑数据上传

添加 GPU readback 验证 buffer 内容：
- skinBuffer、boneIdxBuffer、boneWtBuffer 数据均正确（与 CPU 一致）
- dstBuffer 采样顶点位置合理（无 NaN/Inf/极大值）

### 第三阶段：怀疑 compute 输出管线

添加多个 debug 模式逐步隔离：

| debugMode | 行为 | 结果 |
|---|---|---|
| 1 Passthrough | 直接 u32 拷贝 src→dst | 正常 |
| 2 Bone0Only | `mat4MulVec4(0u, pos4)` | 正常（bone 0 恰好是单位矩阵） |
| 10 BitcastIdentity | `loadF32→storeF32` 恒等 | 正常 |
| 8 HardRotY | 硬编码 45° 旋转，不读 skin buffer | 扭曲 |
| 0 Normal | 完整 4 骨骼加权蒙皮 | 扭曲 |

关键发现：**Passthrough 和 BitcastIdentity 正常，任何修改 position 的模式都扭曲**。

### 第四阶段：怀疑 buffer 双重用途

将 dstBuffer（STORAGE + VERTEX）拆分为 dstBuffer（STORAGE）+ renderVB（VERTEX），中间加 `copyBufferToBuffer`。仍扭曲。

### 第五阶段：绕过 compute shader

实现 `cpuSkinAndUpload()`：CPU 端计算蒙皮，`writeBuffer` 直接上传到 renderVB。**仍扭曲**。

这证明问题不在 compute shader，而在 **VS 读取 renderVB 后的处理逻辑**。

### 第六阶段：验证 flags 传递

在 fragment shader 中添加颜色 tint：
- `flags & 1 != 0` → 绿色（GPU Skinning 跳过 VS 蒙皮）
- `flags & 1 == 0` → 红色（VS 端蒙皮）

结果：**红色**。说明 shader 中 `scene.flags & 1 == 0`，即 flags 未生效。

追查到 `Float32Array` 写入 float 1.0 被 u32 读取为 `0x3F800000`，`& 1 = 0`。

## 教训

1. **Float32Array 和 Uint32Array 共享同一 ArrayBuffer 时，写入类型必须与 shader 读取类型匹配**。`Float32Array[n] = 1` 写入的是 float 位模式，不是整数 1。
2. **WebGPU uniform buffer 中的 u32 字段必须用 Uint32Array/DataView 写入**，不能通过 Float32Array 间接写入。
3. 排查渲染问题时，**尽早验证 uniform 值是否正确传到 shader**（如用颜色编码输出），避免在 shader 逻辑层面深挖而忽略数据传递层。
